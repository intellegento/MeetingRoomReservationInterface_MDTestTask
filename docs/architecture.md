# Архитектура

Требования: [requirements.md](requirements.md). Решения: [open-questions.md → «Решения»](open-questions.md#решения).

## Слои

| Слой | Что внутри | Чего нет |
|------|------------|----------|
| `src/domain` | Типы (`Booking`, `BookingInput`, `RoomNow`), константы (`ROOM_TIMEZONE`, 09:00–18:00, 30/120, шаг 30, `title` ≤ 100), чистые функции: разбор и сравнение времени в минутах, валидация B1–B7, B10–B12, пересечения, варианты конца (B10), перевод момента времени в «сейчас» комнаты (B9), коды ошибок | React, `fetch`, Next.js, `Date.now()`, `new Date()` без аргумента, ввод-вывод |
| `src/server` | Mock API: обработчики запросов, in-memory store на `globalThis`, seed (Q16), разбор запроса (400), маппинг ошибок домена в 422/409/404, dev-флаги (`ENABLE_DEV_TOOLS`, `X-Mock-Force-Conflict`, `X-Mock-Delay`) | React, импорт из `src/api` / `src/features` / `src/components` |
| `src/api` | Клиент сети: интерфейс `BookingsApi`, HTTP-реализация, разбор тела ошибки `{ error: {...} }` в типизированную `ApiError`, base URL | React, импорт из `src/server` |
| `src/features` | Хуки и состояние сценариев: загрузка списка по дате (с отменой гонок), форма (своё состояние, независимое от списка — Q7), мутации и перезапрос (Q15), обработка 409/422/404, dev-панель (Q8) | Бизнес-правила (только вызовы `src/domain`), прямой `fetch` |
| `src/components` | Презентационные компоненты: список, форма, поля, сообщения, состояния U1–U4. Получают данные и колбэки через props | Импорт `src/api`, `src/server`, `src/features`. Сетевые вызовы |
| `src/app` | Next.js: страницы собирают `features` и `components`. `src/app/api/bookings/**/route.ts` — тонкие обёртки над `src/server` | Логика правил |

## Разрешённые направления зависимостей

```
            src/app (страницы)          src/app/api/** (route.ts)
              │        │                        │
              ▼        ▼                        ▼
       src/features ─► src/components       src/server
          │    │            │                   │
          ▼    └──────┐     │                   │
       src/api        ▼     ▼                   │
          │       src/domain ◄──────────────────┘
          └──────────►▲
```

| Откуда ↓ / Куда → | domain | api | server | features | components |
|---|---|---|---|---|---|
| **domain** | — | ✗ | ✗ | ✗ | ✗ |
| **api** | ✓ | — | ✗ | ✗ | ✗ |
| **server** | ✓ | ✗ | — | ✗ | ✗ |
| **features** | ✓ | ✓ | ✗ | — | ✓ |
| **components** | ✓ (типы и чистые функции форматирования) | ✗ | ✗ | ✗ | — |
| **app (страницы)** | ✓ | ✗ | ✗ | ✓ | ✓ |
| **app/api (route.ts)** | ✓ | ✗ | ✓ | ✗ | ✗ |

Ключевые следствия:
- `src/api` и `src/server` не знают друг о друге. Их общий контракт — HTTP и типы из `src/domain`. Поэтому mock можно заменить реальным бэкендом (S2).
- Одни и те же функции `src/domain` проверяют правила и в UI (подсказки), и на сервере (окончательный вердикт, Q1).
- «Сейчас» вычисляется одной функцией `src/domain`, которая переводит переданный момент времени в пояс комнаты. `Date.now()` и `new Date()` без аргументов вызываются только в двух файлах-часах: `src/server/clock.ts` (главные часы) и `src/features/clock.ts` (подсказки). Имена файлов окончательно фиксируются на этапе 1.
- `fetch` вызывается только в `src/api`.

Как проверять: ESLint `no-restricted-imports` по путям слоёв, `no-restricted-syntax` для `Date.now()` / `new Date()` без аргументов везде, кроме двух файлов-часов, `no-restricted-globals` для `fetch` вне `src/api`. Полный список — [testing.md → «Автоматические проверки правил AGENTS.md»](testing.md#автоматические-проверки-правил-agentsmd). Это встроенные правила ESLint, новых зависимостей не нужно. Настройка — на этапе каркаса.
