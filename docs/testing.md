# Тестирование

Требования и критерии: [requirements.md](requirements.md). Уровни: unit (`src/domain`), api (`src/server` через HTTP-контракт), ui (компоненты и хуки, Testing Library), manual.

## Правила

1. **Каждый тест ссылается на ID требования** в начале названия: `it("B5: касание границ 10:00–11:00 и 11:00–12:00 допустимо", ...)`. Если тест не привязан ни к одному ID, он либо лишний, либо в требованиях пробел. Пробел записать в трейс и спросить заказчика.
2. **TDD.** Сначала тесты, потом прогон, где они **красные по правильной причине** (ошибка утверждения, а не опечатка или ошибка импорта). Вывод этого прогона идёт в трейс этапа. Только после команды заказчика пишется код.
3. **Граничные значения обязательны.** Все граничные значения из критериев B1–B12 в [requirements.md](requirements.md) покрыты тестами по одному на значение (`it.each` допустим). Для каждой границы проверяются обе стороны: «ещё можно» и «уже нельзя».
4. **«Сейчас» в тестах фиксировано.** Функции domain получают его параметром. В api/ui-тестах часы подменяются (fake timers или внедрённые часы). Базовая точка: `2026-10-08 10:10:00` по Бишкеку = `2026-10-08T04:10:00Z`.
5. **Domain не мокается.** api- и ui-тесты используют настоящие функции `src/domain`. Подменяются только сеть (на уровне ui: тестовая реализация `BookingsApi` или перехват `fetch`), часы и env-флаги (`ENABLE_DEV_TOOLS`, `NEXT_PUBLIC_ENABLE_DEV_TOOLS`).
6. Запрещены `.skip`, `.only`, `xit`, `it.todo`. Тест нельзя ослаблять или удалять ради прохождения (см. [AGENTS.md](../AGENTS.md)).
7. **`npm run gate`** — единственный критерий «зелёного». Если хоть один шаг упал, gate красный. Состав (скрипты пишутся на этапе 1, без новых зависимостей):
   1. `tsc --noEmit`;
   2. ESLint с правилами из раздела [«Автоматические проверки правил AGENTS.md»](#автоматические-проверки-правил-agentsmd);
   3. `policy-check` — проверки поиском из того же раздела;
   4. все тесты с `TZ=UTC`;
   5. тесты `src/domain` и тесты, помеченные как зависящие от пояса, повторно с `TZ=America/Los_Angeles` (пояс процесса не должен влиять на результат, T1);
   6. `next build`.
8. **Число тестов не уменьшается.** Gate печатает число тестов, трейс этапа его фиксирует. Если число стало меньше, чем в прошлом трейсе, нужно объяснение в трейсе и согласие заказчика.

## Ошибки, которые тесты обязаны ловить

Это типичные ошибки AI-агента. Для каждой нужен хотя бы один тест, который падает, если ошибку внести.

| # | Ошибка | Как тест её ловит | ID |
|---|--------|-------------------|----|
| T1 | **Сдвиг даты в UTC через `toISOString()`.** В 01:30 по Бишкеку `toISOString().slice(0,10)` даёт вчерашнюю дату | Момент `2026-10-07T19:30Z`: «сегодня» = `2026-10-08`, а `2026-10-07` — прошедшая дата. Gate гоняет тест с `TZ=UTC` и `TZ=America/Los_Angeles` | B9, B6 |
| T2 | **`Date.now()` или `new Date()` внутри domain.** Результат зависит от реального времени | Тесты domain передают «сейчас» явно, и при подмене системных часов результат не меняется. Lint-правило запрещает эти вызовы в `src/domain` | B9, B12 |
| T3 | **`<=` вместо `<` (и наоборот) в пересечениях и границах** | Касание `10:00–11:00` / `11:00–12:00` проходит. `17:30–18:00` проходит. `10:00–10:00` отклоняется. Старт = `floor(now)` проходит | B1, B2, B5, B12 |
| T4 | **Самоконфликт при редактировании** | `PATCH id=1` в пределах своего же интервала → 200. Варианты конца в `select` не ограничены собственной бронью | B7, B10 |
| T5 | **Строковое сравнение времени** (`"9:30" > "10:00"`, разный формат) | Невалидный формат → 400. Все сравнения в минутах. Есть случаи, где строковое и числовое сравнение расходятся | B1, B2 |
| T6 | **Форма очищается после 409** | ui: после ответа 409 в полях остаются `14:00`, `15:00`, «Демо», форма открыта, поля времени с `aria-invalid` | B8 |
| T7 | **Список не перезапрашивается после 409** | ui: после 409 уходит ровно один `GET` на дату **из формы**, и в списке видна чужая бронь | B8 |
| T8 | **Двойной submit** | ui: два клика по «Сохранить» до ответа → ровно один `POST` | U4 |
| T9 | **Гонка запросов при смене даты** | ui: выбрать дату A (медленный ответ), затем B (быстрый). В итоге показан список B, поздний ответ A игнорируется | F1, F2 |
| T10 | **Нет серверной валидации** (правила только в UI) | api: каждое правило B1–B7, B10–B12 проверяется прямым HTTP-запросом в обход UI → 400/422/409 | B1–B12 |

## Ручная мутация: проверка качества тестов

Тесты считаются достаточными, только если они ловят намеренную порчу критичных правил. На этапе, где правило реализовано:

1. Внести мутацию в код (по одной за раз), прогнать тесты, убедиться, что хотя бы один тест **красный**.
2. Откатить мутацию (`git checkout -- <файл>`), убедиться, что тесты снова зелёные.
3. Записать в трейс таблицу: мутация → какой тест упал.

Обязательные мутации:
- `<` ↔ `<=` в проверке пересечения (B5);
- убрать исключение собственной брони при редактировании (B7);
- `!==` → `===` или удалить проверку кратности 30 (B10);
- `floor(now)` → `now` с секундами или `start > now` вместо `>=` (B12);
- вычислять «сегодня» через `toISOString().slice(0,10)` (B9);
- удалить проверку прошедшего времени на сервере (B6, T10);
- не перезапрашивать список после 409 (B8);
- сбрасывать форму после ошибки (B8);
- убрать `disabled` у кнопки во время отправки (U4).

Мутация, которая не уронила ни одного теста, — это дыра. Нужно добавить тест и записать случай в `docs/traces/incidents.md`.

## Автоматические проверки правил AGENTS.md

Для каждого правила из раздела «Нельзя» указано, как оно проверяется. Всё, что помечено **gate**, реализуется на этапе 1 и роняет `npm run gate`. Шаблоны поиска — расширенные регулярные выражения, `policy-check` — скрипт на Node без зависимостей.

| Правило AGENTS.md | Проверка | Где |
|-------------------|----------|-----|
| Не читать/менять `.env*` (кроме `.env.example`), не читать `~/.ssh`, не запускать `gh auth token` | Запрет на уровне агента: deny-правила в `.claude/settings.json` (`Read`/`Edit` для `.env*`, `~/.ssh/**`; `Bash(gh auth token*)`) — **предложение, нужно согласие заказчика**. В gate: `git ls-files` не содержит `.env*`, кроме `.env.example`; `.env.example` содержит только строки `ИМЯ=` без значений | settings + gate (`policy-check`) |
| Нет `.skip`, `.only`, `xit`, `it.todo` | Поиск по тестам: `\.(skip\|only\|todo)\(`, `\b(xit\|xdescribe\|fit\|fdescribe)\(` → должно быть пусто. Плюс `allowOnly: false` в настройках раннера | gate (`policy-check`, раннер) |
| `@ts-ignore` / `any` только с записанной причиной | ESLint: `@typescript-eslint/ban-ts-comment` (`ts-ignore`: запрет, `ts-expect-error`: `allow-with-description`, мин. 10 символов), `@typescript-eslint/no-explicit-any`: error. Поиск: строки с `eslint-disable` без ` -- ` → пусто. Запись в трейсе — пункт stage-gate | gate (lint, `policy-check`) + чек-лист |
| Не ослаблять и не удалять тест ради прохождения | Число тестов не уменьшается (правило 8). Ручная мутация (раздел выше) показывает, что тесты ловят ошибки. В stage-gate: просмотр `git diff` тестовых файлов на удалённые `expect` и изменённые ожидаемые значения | gate (печать числа) + чек-лист |
| Бизнес-правила только в `src/domain` | ESLint `no-restricted-syntax`: литералы `"09:00"`, `"18:00"` вне `src/domain` и тестов. api-тесты (T10) проверяют, что сервер применяет правила, а мутации в `src/domain` роняют и unit-, и api-тесты (значит, сервер не дублирует логику) | gate (lint) + мутации |
| Нет `Date.now()` / `new Date()` без аргумента в `src/domain` | ESLint `no-restricted-syntax` для `src/**`, кроме двух файлов-часов: `CallExpression[callee.object.name='Date'][callee.property.name='now']`, `NewExpression[callee.name='Date'][arguments.length=0]` | gate (lint) |
| Не мокать domain в тестах | Поиск: `vi\.mock\([^)]*domain` (и `jest.mock`) в тестах → пусто | gate (`policy-check`) |
| Компоненты не импортируют `src/api` | ESLint `no-restricted-imports` в `src/components/**`: `@/api*`, `@/server*`, `@/features*` и относительные пути на них; `fetch` вне `src/api` запрещён (`no-restricted-globals`) | gate (lint) |
| Новые зависимости только с записью в журнал | `policy-check`: каждое имя из `dependencies` и `devDependencies` в `package.json` встречается в таблице журнала `docs/architecture.md` | gate (`policy-check`) |
| Не коммитить при красном gate | Git-хук `pre-commit` через `git config core.hooksPath .githooks` (без husky) запускает `npm run gate`. Хук создан (`.githooks/pre-commit`), пока запускает только `policy-check --staged`; `npm run gate` добавляется на этапе 1, там же `core.hooksPath` настраивается скриптом `prepare` для свежих клонов. Вывод gate — в трейсе | хук + трейс |
| Не переходить к следующему этапу без команды | Автоматически не проверить. В трейсе этапа N+1 первая строка — цитата команды заказчика на старт | чек-лист stage-gate |
| Любая работа с коммитом пишет `date` в time-log (AGENTS.md, «Время — для любой работы»; INC-2) | **Реализовано** в `scripts/policy-check.mjs`. Хук `pre-commit` (`--staged`): коммит без изменения `docs/time-log.md` отклоняется; добавленные/изменённые строки должны иметь старт и конец в формате `date`. Gate (без флага): каждый коммит после `7158d59` меняет time-log, его строки закрыты, время коммита не раньше конца строки. Строка `0b` — единственная с «не записан»/«не измерен» | хук + gate (`policy-check`) |
| Время только из `date`, без оценок и округлений | `policy-check`: каждая заполненная ячейка «старт»/«конец» в `docs/time-log.md` соответствует формату `date '+%Y-%m-%d %H:%M:%S %z'` (`^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2} [+-]\d{4}$`), «факт» равен разности конца и старта. **Реализовано** в `scripts/policy-check.mjs` | хук + gate (`policy-check`) |
| Если неясно — спросить | Автоматически не проверить. Вопросы и ответы фиксируются в `docs/open-questions.md` или трейсе | ревью (этап 8) |
| Нет секретов в переписке (security.md) | `policy-check`: поиск в `docs/traces/chats/` по шаблонам из security.md (`gho_`, `ghp_`, `github_pat_`, `sk-`, `xox`, `PRIVATE KEY`, `token=`, `secret=`, `password=`) → пусто | gate (`policy-check`) |
