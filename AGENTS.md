# AGENTS.md — правила для AI-агента

## Проект
Интерфейс бронирования одной переговорной (рабочий день 09:00–18:00, пояс `Asia/Bishkek`).
Тестовое задание: инженерная аккуратность важнее дизайна. Таймбокс 4–6 ч.
Next.js + TypeScript strict, mock API на Route Handlers + in-memory store.

## Карта документов
- `docs/tz.md` — ТЗ, единственный источник истины. Не редактировать.
- `docs/requirements.md` — требования с ID (B/F/U/S/A/D) и критериями приёмки.
- `docs/open-questions.md` — спорные места и **решения заказчика** (раздел «Решения»).
- `docs/architecture.md` — слои, направления зависимостей, журнал зависимостей.
- `docs/plan.md` — этапы, таймбоксы, DoD, порядок среза, трассировка ID → этап → тест.
- `docs/testing.md` — правила тестов, состав `npm run gate`, ловушки, автоматические проверки правил «Нельзя».
- `docs/security.md` — что агенту недоступно, кто делает авторизацию и деплой.
- `docs/checklists/stage-gate.md`, `docs/checklists/pre-delivery.md` — чек-листы.
- `docs/time-log.md` — время этапов. `docs/traces/` — трейсы этапов, `INDEX.md`, `incidents.md`, `chats/`.

## Время — для любой работы
Любая работа с коммитом, включая работу вне этапов, начинается и заканчивается
записью `date '+%Y-%m-%d %H:%M:%S %z'` в `docs/time-log.md` (своя строка: этап или
`Nb: <суть>`). Коммит без строки в time-log с заполненными стартом и концом запрещён.
Проверка: `scripts/policy-check.mjs` (хук `pre-commit` и gate).

## Порядок работы над этапом N
1. Получить команду заказчика на этап, прочитать AGENTS.md и нужные docs.
2. Выполнить `date '+%Y-%m-%d %H:%M:%S %z'`, записать вывод целиком как старт в `docs/time-log.md`.
3. Записать в `docs/traces/stage-N.md` цитату команды и план: цель, ID требований, файлы, тесты.
   Допустима только инфраструктура, без которой тесты не запустить (этап 1: каркас и gate).
4. Написать красные тесты, прогнать и показать красный вывод. **СТОП**, ждать команды.
5. Реализация.
6. `npm run gate` — должен быть зелёным.
7. Заполнить трейс доказательствами: вывод gate, что сделано, отклонения. Пройти `docs/checklists/stage-gate.md`.
8. Выполнить `date` тем же форматом, записать конец и факт (конец − старт) в `docs/time-log.md`.
9. Коммит `stage N: <суть> (gate green)` и push. **СТОП**. Этап 0 (только документы, gate ещё нет) — без «(gate green)».

## Нельзя
- Читать или менять `.env*` (кроме `.env.example`). Читать `~/.ssh`. Запускать `gh auth token`.
- Оставлять в тестах `.skip`, `.only`, `xit`, `it.todo`.
- Использовать `@ts-ignore` / `@ts-expect-error` и `any` без записанной причины (комментарий в коде + трейс).
- Ослаблять или удалять тест, чтобы он прошёл.
- Держать бизнес-правила вне `src/domain`.
- Вызывать `Date.now()` и `new Date()` без аргумента в `src/domain`.
- Мокать `src/domain` в тестах.
- Импортировать `src/api` из `src/components`: только через хуки `src/features/`.
- Добавлять зависимость без записи в журнал `docs/architecture.md`.
- Коммитить при красном gate.
- Переходить к следующему этапу без команды заказчика.
- Оценивать или округлять время. В time-log пишется только вывод `date`.
- Добавлять файлы и функции сверх задания. Если они нужны — предложить (что и зачем) и ждать одобрения заказчика.

Как каждое правило проверяется автоматически — `docs/testing.md`, «Автоматические проверки правил AGENTS.md».

## Если неясно
Задай вопрос и жди. Не угадывай. Ответ записать в `docs/open-questions.md` или в трейс этапа.

## Инциденты
Любое отклонение от правил или неожиданная поломка записывается в `docs/traces/incidents.md`
(дата, этап, что случилось, причина, что сделано) и получает ссылку из трейса этапа.
