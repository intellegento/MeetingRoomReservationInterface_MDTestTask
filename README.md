# Meeting Room Reservation Interface

Интерфейс бронирования переговорной комнаты. ТЗ: [docs/tz.md](docs/tz.md).

_README в разработке._

## Деплой

Проект собирается и запускается на Vercel без настроек: Framework Preset — Next.js, команды по умолчанию
(`npm ci`, `next build`), Node.js 22.13 или новее (`engines` в `package.json`). Секретов, токенов и внешних
сервисов нет: mock API работает внутри того же приложения (`/api/bookings`).

### Переменные окружения

Все переменные необязательны и несекретны. Без них приложение работает как обычный интерфейс без dev-инструментов.
Флаги включает только строка `true`, любое другое значение — выключено.

| Переменная | Где читается | По умолчанию | На демо |
|------------|--------------|--------------|---------|
| `NEXT_PUBLIC_ENABLE_DEV_TOOLS` | клиент, **встраивается при сборке** | выключено: dev-панели нет | `true`, если нужна демонстрация конфликта (B8) и медленной сети |
| `ENABLE_DEV_TOOLS` | сервер, на каждый запрос | выключено: заголовки `X-Mock-*` игнорируются | `true` вместе с предыдущей |
| `DISABLE_MOCK_DELAY` | сервер | задержка ответа 300–800 мс (видно состояние загрузки) | не задавать |
| `NEXT_PUBLIC_API_URL` | клиент, встраивается при сборке | `/api` (встроенный mock) | не задавать; нужна при замене mock на реальный API |
| `ALLOWED_DEV_ORIGINS` | только `next dev` | пусто | не нужна |

**Что видит проверяющий:**

- Оба флага `true` — внизу экрана блок «Инструменты разработчика» с переключателями «Симулировать конфликт
  при следующем сохранении» (сервер ответит 409 с «чужой» бронью) и «Медленная сеть» (задержка 2 с,
  видно «Сохраняем…»). Без этого конфликт (B8) можно увидеть только двумя вкладками, а на serverless — ненадёжно (см. ниже).
- Оба выключены — dev-панели нет, сервер не реагирует на `X-Mock-*`.
- Включён только `NEXT_PUBLIC_ENABLE_DEV_TOOLS` — панель видна, но переключатели ничего не делают. Так не настраивать.

Переменные задаются в Vercel: Project → Settings → Environment Variables. `NEXT_PUBLIC_*` встраивается в клиентский
код при сборке, поэтому после изменения любой переменной нужен новый деплой (Deployments → Redeploy).

Флаги на демо открывают заголовки `X-Mock-*` любому посетителю. Это допустимо: данные — только in-memory mock,
задержка ограничена 10 с.

### Ограничение: in-memory store на serverless

Брони хранятся в памяти процесса (Q9). На Vercel API работает в serverless-функциях, и у каждого инстанса своя память:

- состояние сбрасывается при холодном старте и новом деплое — созданные, изменённые и удалённые брони пропадают;
- если запросы попадают в разные инстансы, бронь, созданная или изменённая в одном, не видна в другом;
- seed детерминирован (после J2): каждый инстанс при первом обращении создаёт одни и те же брони с одинаковыми
  id `seed-<дата>-<n>` от «сегодня» по поясу `Asia/Bishkek`, поэтому правка и удаление seed-броней не дают
  ложного «Бронь уже удалена» из-за расхождения id;
- «чужая» бронь из «Симулировать конфликт» может не появиться в списке после перезапроса, если он ушёл в другой
  инстанс. Сообщение о конфликте и сохранённые данные формы видны всегда.

Для постоянного хранения нужен реальный бэкенд: mock заменяется через `NEXT_PUBLIC_API_URL` и интерфейс `BookingsApi`.
